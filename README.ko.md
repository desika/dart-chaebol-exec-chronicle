# dart-exec-chronicle

**한국 상장사 임원 전원의 생애를 공시에서 복원한다. 명령 한 줄, HTML 파일 하나.**

한국어 · [English](README.md)

---

한국 대기업에서 임원은 몇 살에 되는가. 상무는 몇 년을 버티다가 사업보고서에서 조용히 사라지는가. 사장은 안에서 올라오는가, 그룹에서 내려오는가. 어느 학교 어느 과 출신이 많고, 사장은 퇴직금으로 얼마를 받고 나가는가.

대기업 임원은 한국에서 가장 주목받으면서도 가장 기록이 없는 사람들입니다. 해마다 12월 "연말 인사"가 기사로 쏟아지고 나면 거기서 끝입니다. 그런데 자료는 처음부터 있었습니다. 상장사는 매 분기·매년 임원현황, 개인별 보수, 퇴직금, 대표이사 변경을 금융감독원 전자공시(DART)에 올립니다. 다만 수백 개 보고서에 흩어져 있고, 표 형식이 제각각이며, 같은 사람의 표기가 해마다 달라질 뿐입니다.

이 도구는 그것을 다시 꿰맵니다. 회사 이름 하나를 넣으면 DART에서 임원현황 표, 보수 공시, 보고서 원문, 대표이사 변경 공시를 전부 가져와, 연도를 넘나드는 동일 인물을 묶고(이름 + 출생연월), 선임·승진·퇴임 시점을 정하고, 사장 계보를 잇고, 대학 동문을 연결해, **더블클릭으로 열리는 단일 HTML 파일(임원 도감)** 로 만듭니다.

Python 표준 라이브러리만 씁니다. 외부 패키지도, 서버도, 설치할 DB도 없습니다.

## 이런 질문에 답할 수 있습니다

- 한국 대기업 임원은 몇 살에 되는가. (LG이노텍 2017년 이후 선임자: 47세와 50세가 가장 많다)
- 상무는 몇 년을 버티다가 공시에서 사라지는가.
- 사장은 안에서 올라오는가, 그룹에서 내려오는가. (LG이노텍: LG전자·LG화학에서 두 번 파견, 그다음 내부 승진 한 번)
- 어느 학교, 어느 전공인가. 경영진의 몇 %가 수도권 대학인가, MBA는 몇 명인가. (62%, 1%)
- R&D 출신과 영업 출신, 스태프 출신 중 누가 승진하는가. (2021~2025 신임 36명: R&D 39%, 스태프 22%, 현장 영업 0%)
- 사장은 얼마를 받고, 퇴직금으로 얼마를 들고 나가는가. (현 사장 9.91억 → 9.39억 → 12.51억 원, 2022~2025)
- 같은 학교 같은 과정을 같은 시기에 다닌 사람이 지금 같은 임원실에 있는가.
- 어느 자리가 등용문인가. 현 사장 전에 그 자리를 거친 사람은 누구이고 어디로 갔는가.

숫자 하나하나가 출처 공시로 이어집니다.

## 무엇이 나오나

**LG이노텍**을 2016~2025 사업보고서와 2026 분기보고서로 돌린 예입니다. 약 1분이 걸렸고 결과는 이렇습니다.

- 임원 131명의 생애 전체, 그중 현직 49명
- 사장 계보 3명: 박종석(2016-04, LG전자에서 파견) → 정철동(2019-01, LG화학에서) → 문혁수(2024-03, 내부 승진. 2015년 45세에 상무 선임)
- 사장 재임 중앙값 4년, 사장 선임 나이 중앙값 58세
- 2021~2025년 신임 임원 36명 중 R&D 출신 39%, 스태프 출신 22%, 지역·현장 영업 출신 0%
- 수도권 대학 출신 62%, MBA 보유 1%
- 현 사장의 공시 보수: 9.91억(2022) → 9.39억(2024) → 12.51억 원(2025)

## 빠른 시작

Python 3.10 이상. 설치할 패키지 없음. (렌더 검사 `check_app.py`만 Windows의 Edge를 씁니다. 선택 사항)

```
# 1) DART 인증키 (https://opendart.fss.or.kr 에서 무료 발급)
set DART_API_KEY=발급받은키          # macOS/Linux: export DART_API_KEY=...
#    또는 저장소 루트에 dart_key.txt 파일로 저장 (git 제외됨)

# 2) 회사 한 줄
set PYTHONUTF8=1                     # Windows 콘솔 한글
python add_company.py LG이노텍
```

끝나면 `dist/App_LG이노텍_<버전>.html` 이 생깁니다. 최근 10년(2016 사업연도~)을 기본으로 수집하며, 보고서 수에 따라 1~20분 걸립니다. `삼성전자`, `SK하이닉스`, `현대자동차`, `LG에너지솔루션` 등 상장사 약 2,600곳 어디든 됩니다.

### 옵션

| 옵션 | 뜻 | 예 |
|---|---|---|
| `이름` 또는 `corp_code` | DART 회사명(부분 일치, 상장사 우선) 또는 8자리 고유번호 | `삼성E&A`, `00126308` |
| `--slug` | 폴더 이름(영문). 없으면 영문 회사명에서 자동 | `--slug sena` |
| `--group` | 그룹 프리셋(삼성·LG·SK·현대·롯데·한화·CJ·none). 회사명이 그룹명으로 시작하면 자동 | `--group 삼성` |
| `--self` | 자사의 전신·별칭(경력 문구에서 자사 보직으로 인식, 계열사 목록에서 제외) | `--self 삼성엔지니어링` |
| `--first` | 첫 사업연도(기본 2016) | `--first 2010` |
| `--logo` | 머리글 로고 파일(선택) | `--logo logo.svg` |
| `--no-fetch` | 수집 생략, 파싱·빌드·렌더만 다시 | |

회사명이 바뀐 회사(예: 삼성엔지니어링 → 삼성E&A)는 DART 고유번호가 같으므로 현재 이름으로 넣고 옛 이름을 `--self`에 적어 주면 됩니다.

## Claude Code에서 쓰기 (스킬 + MCP)

이 저장소는 Claude Code 플러그인이기도 합니다. 작업 절차와 데이터 필드를 아는 **스킬**, 그리고 표준 라이브러리로만 짠 **MCP 서버**(`mcp_server.py`, stdio)에 도구 9개가 있습니다: `search_company`, `build_company`(백그라운드 실행), `build_status`, `list_companies`, `company_summary`, `query_people`, `find_person`, `ceo_succession`, `classmates`.

```
/plugin marketplace add desika/dart-exec-chronicle
/plugin install dart-exec-chronicle@dart-exec-chronicle
```

그다음은 말로 합니다.

```
> LG이노텍 임원 도감 만들어 줘
> 현대자동차 사장 계보랑 평균 취임 나이 알려 줘
> 삼성전자에서 2021년 이후 선임된 상무 중 서울대 출신만 뽑아 줘
```

플러그인 없이도 저장소를 clone 해서 그 안에서 `claude`를 띄우면 `.mcp.json`의 MCP 서버가 등록되고, 절차는 `skills/dart-exec-chronicle/SKILL.md`를 읽히면 됩니다. 다른 MCP 클라이언트(Claude Desktop 등)는 아래 설정으로 붙습니다.

```json
{ "mcpServers": { "dart-exec-chronicle": { "command": "python", "args": ["/path/to/dart-exec-chronicle/mcp_server.py"], "env": { "DART_API_KEY": "발급받은키", "PYTHONUTF8": "1" } } } }
```

## 파이프라인

`add_company.py`가 아래를 순서대로 실행합니다. 각 단계는 환경변수 `COMPANY=<slug>`를 주고 따로 실행할 수도 있습니다.

| 단계 | 스크립트 | 입력 → 출력 |
|---|---|---|
| 수집 | `fetch_dart.py` | 임원현황 API `exctvSttus`(사업보고서 + 모든 분기·반기) → `exec_raw.json`, SQLite |
| 수집 | `fetch_docs.py` | 보고서 원문 `document.xml`(zip) → `docs/*.xml`. 2013년 이전은 `list.json`으로 사업보고서 탐색 |
| 수집 | `fetch_pay.py` | 보수 API 5종 → `pay_raw.json` |
| 수집 | `fetch_ceo_changes.py` | '대표이사 변경' 수시공시 → `ceo_changes.json` |
| 수집 | `fetch_affiliates.py` | (설정 시) 자회사 감사보고서·임원의변동·기업집단현황 → `affil_raw.json` |
| 파싱 | `parse_exec_docs.py` | 원문 임원현황 표 → 미등기임원 복원, `exec_raw`에 병합 |
| 파싱 | `parse_pay.py` | 원문 '개인별 보수지급금액 산정기준' 표 → `pay_detail.json` |
| 분석 | `analyze.py` | 인물 단위 병합(이름 + 출생연월), 선임일·퇴임·학력·경력 파싱 → `persons.json/csv` |
| 빌드 | `build_data.py` | 트랙·출신 그룹·부문·사장 계보·동문 엣지·이벤트 → `app_data.json` |
| 빌드 | `build_affil.py` | 사장 임기표, 자회사 임기표·예측 보드 → `affil.json` |
| 렌더 | `render_app.py` | `app_template.html` + 데이터 → `dist/App_<회사>_<버전>.html` |
| 검사 | `check_app.py` | 헤드리스 Edge로 전원 상세 + 7개 탭 호출, JS 오류 확인 |

`careerlib.py`는 경력 문구 파서(학교·전공·학위 추출, 한 덩어리 경력 분리)이고 `company.py`가 설정을 읽습니다.

## 만든 뒤 할 일: 그루핑 교정

`companies/<slug>/data/group_map.json` 이 "선임 당시 보직 → 출신 그룹" 규칙입니다. 처음엔 범용 규칙(영업·R&D·경영지원 등 12개)이라 그 회사 조직 어휘가 빠져 '미분류'가 남습니다. `add_company.py` 마지막에 미분류 목록이 찍히니 규칙(`rules`, 위에서부터 첫 매치)이나 이름별 `overrides`를 추가하고 다시 빌드합니다.

```
set COMPANY=lginnotek
python build_data.py && python build_affil.py && python render_app.py
```

`companies/<slug>/config.json`의 항목(자사·그룹 표기 정규식, 연도 범위, 부문 규칙, 자회사, 이벤트 등)은 [companies/README.md](companies/README.md)에 있습니다.

## 판정 규칙(요약)

- **동일 인물** = 이름(공백 제거) + 출생연월. 출생월 오기는 병합 규칙으로 흡수.
- **임원 선임일** = 보고서들의 재직기간 시작일 중 가장 이른 날짜. 없으면 첫 공시 연도 말로 추정(≤ 표시).
- **퇴임** = 퇴직소득이 공시된 보고서 연도가 마지막 등장 보고서 연도와 같으면 그해 12월, 다르면 1월. 공시가 없으면 마지막 등장 연도 12월. 분기보고서까지 수집해 연중 취임·퇴임을 분기 단위로 좁힘.
- **사장** = 자사 대표이사(직위 또는 담당업무 시작, '대표이사 보좌역' 제외) 또는 대표이사 변경 공시. 임기 종료 = 후임 취임일. 공동대표 체제는 개인별.
- **트랙** = 사장(그룹 파견 / 내부 승진) · 그룹 전입 임원 · 내부 성장 임원 · 사외이사·감사.
- **직위 연차** = 마지막 승진 인사연도 기준(사장은 취임 기준). 삼성 계열은 2021-12 전무 폐지를 반영(`title_merge_year`).
- **동문** = 같은 학교 + 같은 과정. 고졸은 잇지 않음. 졸업연도 차이가 과정 길이 안이면 '같이 다녔을 듯'.

자세한 규칙과 예외는 앱의 '자료·규칙' 탭과 코드 주석에 있습니다.

## 한계

- 사업보고서가 적은 회사(비상장·소규모)는 복원 범위가 좁습니다. 미등기임원은 회사에 따라 원문에만 있습니다.
- 재직기간을 "N년 M개월"로만 적는 회사는 선임일이 추정값(≤)이 됩니다.
- 입사연도·팀장 임명연도·고과는 공시되지 않습니다. 출신 그룹·부문은 문구 기반 추정입니다.
- 5억 원 미만 보수는 개인별 공시가 없어 상무급 퇴직금은 대부분 보이지 않습니다.
- 그룹 프리셋은 7개 그룹만 있습니다. 다른 그룹은 `--group none`으로 만들고 설정의 `group_regex`를 직접 채우면 됩니다.

## 데이터에 관하여

이 도구는 DART에 공개된 정기·수시공시만 읽습니다. 저장소에는 코드만 있고, 실행 결과(설정·수집 데이터·HTML)는 각자 로컬에 남습니다(`.gitignore`). 결과물을 공유할 때의 판단은 사용하는 사람의 몫입니다.

## 방향과 참여

다음 단계는 모델입니다. 여러 회사를 같은 규칙으로 돌려 생애를 쌓고, 선임 나이·직위 연차·출신·학력·그룹 소속에 따라 승진·퇴임 확률이 어떻게 달라지는지 학습하는, 한국 대기업 임원 커리어의 파운데이션 모델입니다. 이슈·PR을 환영합니다.

- 회사별 `group_map.json` 어휘 규칙, 그룹 프리셋 추가
- 옛 보고서·비정형 머리글 표 파서 보강
- 재직기간·학력 문구 파싱 예외
- 모델(특징 설계, 학습 스크립트)
